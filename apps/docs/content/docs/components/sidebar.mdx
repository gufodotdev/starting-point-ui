This is a full-screen component, so the previews on this page are limited and may not work on mobile. For full, ready-to-use examples, visit the [sidebar examples](/examples/components/sidebar).
</Callout>

## Usage

A sidebar layout pairs a `sidebar` root with a `sidebar-panel` and the `sidebar-page` content area. Point the panel at its trigger with `data-sp-toggle`.

The panel is a flex column of three pieces: a `sidebar-header` and `sidebar-footer` that stay pinned, and a scrollable `sidebar-content` between them holding the menu. Below the sidebar breakpoint (1024px by default) the trigger opens the panel as a modal drawer with a dimmed backdrop; above it, the trigger collapses and expands the column in place.

| Class                  | Applies to                                              |
| ---------------------- | ------------------------------------------------------- |
| `sidebar`              | The layout root wrapping the panel and page             |
| `sidebar-panel`        | The panel itself; carries `data-sp-toggle`              |
| `sidebar-header`       | A pinned region at the top of the panel                 |
| `sidebar-content`      | The scrollable middle holding the groups                |
| `sidebar-footer`       | A pinned region at the bottom of the panel              |
| `sidebar-group`        | A labelled section of the menu                          |
| `sidebar-group-label`  | The group's heading                                     |
| `sidebar-group-content`| Wraps the group's menu                                  |
| `sidebar-menu`         | A list of menu items                                    |
| `sidebar-menu-item`    | A single row in the menu                                |
| `sidebar-menu-button`  | The link or button inside an item                       |
| `sidebar-page`         | The main content area beside the panel                  |

```html
<div class="sidebar">
  <aside class="sidebar-panel" data-sp-toggle="#sidebar-trigger">
    <header class="sidebar-header">
      <a href="#" class="sidebar-menu-button sidebar-menu-button-lg">...</a>
    </header>
    <div class="sidebar-content">
      <div class="sidebar-group">
        <span class="sidebar-group-label">Platform</span>
        <div class="sidebar-group-content">
          <nav class="sidebar-menu">
            <div class="sidebar-menu-item">
              <a href="#" class="sidebar-menu-button active">
                <span>Dashboard</span>
              </a>
            </div>
            <div class="sidebar-menu-item">
              <a href="#" class="sidebar-menu-button">
                <span>Projects</span>
              </a>
            </div>
          </nav>
        </div>
      </div>
    </div>
    <footer class="sidebar-footer">
      <button class="sidebar-menu-button sidebar-menu-button-lg">...</button>
    </footer>
  </aside>
  <main class="sidebar-page">
    <button id="sidebar-trigger" class="btn btn-ghost btn-icon" aria-label="Toggle sidebar">...</button>
    ...
  </main>
</div>
```

See it running in the [sidebar examples](/examples/components/sidebar).

## Options

Set each option with its own `data-sp-*` attribute on the panel.

| Attribute        | Type   | Default | Description                                     |
| ---------------- | ------ | ------- | ----------------------------------------------- |
| `data-sp-toggle` | String | —       | Selector for the element that toggles the panel |

The collapse mode is set with the `data-collapse` attribute on the panel (`offcanvas` or `icon`) so the correct first paint happens before JavaScript loads.

---

## Events

The mobile drawer fires the lifecycle events on the panel; `before*` events are cancelable. The desktop column fires `sp-collapse` and `sp-expand`, also cancelable.

| Event           | When                                      |
| --------------- | ----------------------------------------- |
| `sp-beforeshow` | Before the drawer opens (cancelable)      |
| `sp-show`       | Drawer opening                            |
| `sp-shown`      | Drawer open and settled                   |
| `sp-beforehide` | Before the drawer closes (cancelable)     |
| `sp-hide`       | Drawer closing                            |
| `sp-hidden`     | Drawer closed                             |
| `sp-collapse`   | The desktop column collapses (cancelable) |
| `sp-expand`     | The desktop column expands (cancelable)   |

```js
// Persist the desktop state, e.g. into a cookie the server can render from.
panel.addEventListener("sp-collapse", () => saveState("collapsed"));
panel.addEventListener("sp-expand", () => saveState("expanded"));
```

---

## Methods

Get the instance with `sp.sidebar(el)`, then call its methods:

| Method     | Description                                                       |
| ---------- | ---------------------------------------------------------------- |
| `toggle()` | Open or close the drawer on mobile, collapse or expand on desktop |
| `show()`   | Open the mobile drawer                                            |
| `hide()`   | Close the mobile drawer                                           |

```js
const sidebar = sp.sidebar(document.querySelector(".sidebar-panel"));

sidebar.toggle();
```

## Accessibility

The trigger's `aria-expanded` and `aria-controls` are wired automatically and reflect the current viewport: the drawer on mobile, the collapsed column on desktop. On mobile the open drawer adheres to the [Dialog (Modal) WAI-ARIA design pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): it sets `role="dialog"` and `aria-modal`, moves focus into the panel on open, returns focus to the trigger on close, and closes on Escape.

Use landmark elements as in the examples, an `<aside>` for the panel and `<nav>` for the menu, so screen reader users can jump between regions.
