title: Sidebar
description: An accessible sidebar for Tailwind CSS application layouts, a collapsible column on desktop and a drawer on mobile.

A layout for dashboards and admin panels: an in-flow collapsible column on desktop, an off-canvas drawer with a backdrop on mobile.

## Basic Usage

A sidebar layout pairs a `sidebar` root with a `sidebar-backdrop`, a `sidebar-panel`, and the `sidebar-page` content area. Add `data-sp-sidebar` to the panel with a `toggle` option pointing at the trigger's `id`.

The panel is a flex column of three pieces: a `sidebar-header` and `sidebar-footer` that stay pinned, and a scrollable `sidebar-content` between them holding the menu. Below the sidebar breakpoint (1024px by default) the trigger opens the panel as a modal drawer; above it, the trigger collapses and expands the column in place.

```html
<div class="sidebar">
  <div class="sidebar-backdrop"></div>
  <aside class="sidebar-panel" data-sp-sidebar="toggle: #sidebar-trigger">
    <header class="sidebar-header">
      <a href="#" class="sidebar-menu-button sidebar-menu-button-lg">
        <svg><!-- logo --></svg>
        <span>Acme Inc</span>
      </a>
    </header>
    <div class="sidebar-content">
      <div class="sidebar-group">
        <span class="sidebar-group-label">Platform</span>
        <nav class="sidebar-menu">
          <div class="sidebar-menu-item">
            <a href="#" class="sidebar-menu-button active">
              <svg><!-- icon --></svg>
              <span>Dashboard</span>
            </a>
          </div>
          <div class="sidebar-menu-item">
            <a href="#" class="sidebar-menu-button">
              <svg><!-- icon --></svg>
              <span>Projects</span>
            </a>
          </div>
        </nav>
      </div>
    </div>
    <footer class="sidebar-footer">
      <a href="#" class="sidebar-menu-button sidebar-menu-button-lg">
        <svg><!-- avatar --></svg>
        <span>gufo.dev</span>
      </a>
    </footer>
  </aside>
  <main class="sidebar-page">
    <header class="flex items-center gap-4 border-b p-4">
      <button id="sidebar-trigger" class="btn btn-ghost btn-icon" aria-label="Toggle sidebar">
        <svg><!-- menu icon --></svg>
      </button>
      <h1>Dashboard</h1>
    </header>
    <div class="p-6">Your content here</div>
  </main>
</div>
```

See it running in the [sidebar examples](/examples/components/sidebar).

## Collapse mode

Set `data-collapse` on the panel to choose how it collapses on desktop:

- `offcanvas` (default) slides the whole panel away and the page reclaims the space.
- `icon` shrinks the panel to a rail showing each menu button's leading icon.

```html
<aside class="sidebar-panel" data-collapse="icon" data-sp-sidebar="toggle: #sidebar-trigger">
  ...
</aside>
```

In `icon` mode each menu button needs a leading icon and a `<span>` label: the rail keeps the icon and hides the label, and a tooltip with the label appears on hover. Buttons without a leading icon, group labels, submenus, and badges are hidden in the rail. For brand rows in the header and footer, use a `sidebar-menu-button-lg` with a `size-8` logo or [avatar](/docs/components/avatar) so it fills the rail.

## Initially collapsed

Add the `collapsed` class to the panel to render it collapsed on first paint, before JavaScript loads, and set `aria-expanded="false"` on the trigger so its state matches.

```html
<aside class="sidebar-panel collapsed" data-collapse="icon" data-sp-sidebar="toggle: #sidebar-trigger">
  ...
</aside>
```

## Right side

Add `sidebar-right` to position the panel on the right. Without it, the panel defaults to the left.

```html
<aside class="sidebar-panel sidebar-right" data-sp-sidebar="toggle: #sidebar-trigger">
  ...
</aside>
```

## Inset

Add `sidebar-inset` to the root for an inset main content area with rounded corners and a shadow.

```html
<div class="sidebar sidebar-inset">
  <div class="sidebar-backdrop"></div>
  <aside class="sidebar-panel" data-sp-sidebar="toggle: #sidebar-trigger">...</aside>
  <main class="sidebar-page">...</main>
</div>
```

## Submenus

Use a [collapsible](/docs/components/collapsible) with a `sidebar-menu-sub` for nested navigation. Author `aria-expanded="true"` on the trigger and `shown` on the panel to start expanded.

```html
<div class="sidebar-menu-item">
  <button id="submenu-trigger" class="sidebar-menu-button" aria-expanded="true">
    <svg><!-- icon --></svg>
    <span>Playground</span>
    <svg class="ml-auto in-aria-expanded:rotate-90"><!-- chevron --></svg>
  </button>
  <div class="collapsible-panel shown" data-sp-collapsible="toggle: #submenu-trigger">
    <ul class="sidebar-menu-sub">
      <li class="sidebar-menu-sub-item"><a href="#" class="sidebar-menu-sub-button"><span>History</span></a></li>
      <li class="sidebar-menu-sub-item"><a href="#" class="sidebar-menu-sub-button"><span>Starred</span></a></li>
    </ul>
  </div>
</div>
```

## Options

Set options in the `data-sp-sidebar` value, separated by semicolons.

| Option   | Type   | Default | Description                                     |
| -------- | ------ | ------- | ----------------------------------------------- |
| `toggle` | String | —       | Selector for the element that toggles the panel |

The collapse mode is set with the `data-collapse` attribute on the panel (`offcanvas` or `icon`) so the correct first paint happens before JavaScript loads.

## Events

The mobile drawer fires the lifecycle events on the panel; `before*` events are cancelable. The desktop column fires `sp-collapse` and `sp-expand`, also cancelable.

| Event           | When                                      |
| --------------- | ----------------------------------------- |
| `sp-beforeshow` | Before the drawer opens (cancelable)      |
| `sp-show`       | Drawer opening                            |
| `sp-shown`      | Drawer open and settled                   |
| `sp-beforehide` | Before the drawer closes (cancelable)     |
| `sp-hide`       | Drawer closing                            |
| `sp-hidden`     | Drawer closed                             |
| `sp-collapse`   | The desktop column collapses (cancelable) |
| `sp-expand`     | The desktop column expands (cancelable)   |

```js
// Persist the desktop state, e.g. into a cookie the server can render from.
panel.addEventListener("sp-collapse", () => saveState("collapsed"));
panel.addEventListener("sp-expand", () => saveState("expanded"));
```

## Methods

Get the instance with `sp.sidebar(el)`, then call its methods:

| Method     | Description                                                       |
| ---------- | ---------------------------------------------------------------- |
| `toggle()` | Open or close the drawer on mobile, collapse or expand on desktop |
| `show()`   | Open the mobile drawer                                            |
| `hide()`   | Close the mobile drawer                                           |

```js
const sidebar = sp.sidebar(document.querySelector(".sidebar-panel"));

sidebar.toggle();
```

## Accessibility

The trigger's `aria-expanded` and `aria-controls` are wired automatically and reflect the current viewport: the drawer on mobile, the collapsed column on desktop. On mobile the open drawer adheres to the [Dialog (Modal) WAI-ARIA design pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): it sets `role="dialog"` and `aria-modal`, moves focus into the panel on open, returns focus to the trigger on close, and closes on Escape.

Use landmark elements as in the examples, an `<aside>` for the panel and `<nav>` for the menu, so screen reader users can jump between regions.
