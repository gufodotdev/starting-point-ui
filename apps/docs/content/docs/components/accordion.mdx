A stack of collapsible sections. Opening one closes the others, unless you allow multiple to stay open.

```html preview
<div class="accordion max-w-md">
  <h3>
    <button id="accordion-1" class="accordion-trigger">
      Is it accessible?
      <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" class="text-muted-foreground in-aria-expanded:rotate-180"><path d="m6 9 6 6 6-6"/></svg>
    </button>
  </h3>
  <div class="collapsible" data-sp-toggle="#accordion-1">
    <div class="collapsible-content accordion-content">
      Yes. It adheres to the WAI-ARIA accordion pattern with all wiring done for you.
    </div>
  </div>
  <h3>
    <button id="accordion-2" class="accordion-trigger">
      Is it styled?
      <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" class="text-muted-foreground in-aria-expanded:rotate-180"><path d="m6 9 6 6 6-6"/></svg>

  <div class="collapsible" data-sp-toggle="#accordion-2">

      Yes. It ships with default styles you can override with utilities.
    </div>
  </div>
```

## Usage

An accordion is a group of [collapsibles](/docs/components/collapsible) that close each other. Each section is a trigger and a collapsible that points back at it with `data-sp-toggle`, exactly as a standalone collapsible. Wrapping them in `accordion` adds the single-open rule and the accordion ARIA roles.

Per the [WAI-ARIA pattern](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/), wrap each trigger in a heading (`h2`-`h6`) that matches your page outline. Add `accordion-trigger` to the button for the header styling and `accordion-content` to the panel body for its spacing.

| Class               | Applies to                                              |
| ------------------- | ------------------------------------------------------- |
| `accordion`         | The container that coordinates the sections             |
| `accordion-trigger` | The header button inside each heading                   |
| `accordion-content` | The panel body, alongside `collapsible-content`         |

```html
<div class="accordion">
  <h3>
    <button id="section-1" class="accordion-trigger">Section one</button>
  </h3>
  <div class="collapsible" data-sp-toggle="#section-1">
    <div class="collapsible-content accordion-content">First panel</div>
  </div>
  <h3>
    <button id="section-2" class="accordion-trigger">Section two</button>
  </h3>
  <div class="collapsible" data-sp-toggle="#section-2">
    <div class="collapsible-content accordion-content">Second panel</div>
  </div>
</div>
```

## Examples

### Multiple open sections

Add `data-sp-multiple` so opening a section keeps the others open. Combine it with the `shown` class to start several sections expanded.


### Initially open

Add the `shown` class to a panel so it renders open on first paint, before JavaScript loads. Also set `aria-expanded="true"` on its trigger so the header and its icon paint in the open state too. On init the accordion settles the state without replaying the enter animation.

## Options

Set each option with its own `data-sp-*` attribute on the accordion.

| Attribute          | Type    | Default | Description                             |
| ------------------ | ------- | ------- | --------------------------------------- |
| `data-sp-multiple` | Boolean | `false` | Opening a section keeps the others open |

---

## Events

Each panel is a [Collapsible](/docs/components/collapsible), so the full lifecycle (`sp-beforeshow` through `sp-hidden`) fires on the panels and bubbles to the accordion container.

```js
accordion.addEventListener("sp-shown", (e) => {
  console.log("opened:", e.target); // the collapsible panel
});
```

---

## Methods

Each panel is a Collapsible instance; control one with `sp.collapsible(panel)`:

```js
const panel = document.querySelector("#my-accordion .collapsible");

sp.collapsible(panel).show();
```

## Accessibility

The accordion adheres to the [Accordion WAI-ARIA design pattern](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/). Each trigger gets `aria-expanded` and `aria-controls`, and each panel is labelled as a `region` by its trigger, automatically. Wrap each trigger in a heading matching your page's structure, as in the examples.

| Key               | Action                               |
| ----------------- | ------------------------------------ |
| `Enter` / `Space` | Toggles the focused section          |
| `Tab`             | Moves focus to the next trigger      |
